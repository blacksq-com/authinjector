# AuthInjector import template.
#
#   cp keys.example.txt ~/aj-keys.txt && chmod 600 ~/aj-keys.txt
#   $EDITOR ~/aj-keys.txt                 # replace every PASTE_... placeholder
#   sudo authinjector import ~/aj-keys.txt
#   sudo systemctl restart authinjector
#   shred -u ~/aj-keys.txt
#
# Format:  service[/label]:key:callers[:rate]
#          callers are comma separated; rate is calls per minute, optional.
#
# 🔴 RE-RUNNING THIS FILE IS SAFE. `import` skips any key already configured
# and tells you which, so a second run does nothing at all. `import -f` replaces
# them instead — that is the destructive one, and it will happily write a
# PASTE_ placeholder over a working key, so only use it on a file you have
# actually filled in. `authinjector add` refuses an existing label for the same
# reason, and takes -f too.
#
# 🔴 THE FILLED-IN COPY IS A CREDENTIAL FILE. Keep it at mode 600, outside this
# repo, and shred it after importing. `import` refuses nothing on your behalf:
# it warns if the file is group- or world-readable, and it is all-or-nothing,
# so a single bad line imports none of them.
#
# 🔴 WHY SOME LINES CARRY A LABEL AND OTHERS DO NOT. A service you hold ONE key
# for is written bare and called as /service/... . A service you hold SEVERAL
# keys for has every one of them labelled and NO default, so a caller that
# forgets the label gets a 404 listing the labels rather than silently spending
# the wrong account. Each label carries its own callers and its own rate limit.
#
# `callers` is set to `alice` throughout. Change it per line — that field is the
# whole point of the broker. In particular cloudflare-rw below can destroy
# infrastructure, so give it the narrowest caller list you can live with.

# ── Deliberately absent ─────────────────────────────────────────────────────
#
# These were on your list. They are credentials, but not ones a header- or
# query-injecting proxy can carry, so there is no line for them here and no
# entry in the catalogue. Reasons in full at the foot of catalogue.toml.
#
#   CLOUDFLARE_R2_ACCESS_ID / CLOUDFLARE_R2_SECRET_KEY
#       S3 SigV4 — the secret signs the request, there is no field to inject.
#   DOCUSEAL_WEBHOOK_SECRET
#       Verifies INBOUND webhooks; never travels outbound.
#   GOOGLE_OAUTH_ID_BLACKSQ / GOOGLE_OAUTH_SECRET
#       Browser redirect flow, not a proxied API call.
#   STRIPE_SENDBOX_PUBLISHABLEKEY
#       Publishable by design — ships in client code, not a secret.
#   CLOUDFLARE_ACCOUNT_ID / CLIO_DEV_CLIENT_ID
#       Identifiers, not credentials. Ordinary config.
#   GOOGLE_BUSINESS_PROFILE
#       Was here; removed after the live API answered 401 "Expected OAuth 2
#       access token". Business Profile needs a short-lived OAuth token minted
#       per request, which a static credential cannot be.
#
